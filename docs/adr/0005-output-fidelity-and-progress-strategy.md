# 0.6.0 输出保真与进度策略

## 背景

0.5.2 已解决“翻译失败不导入 PDF”。但公开论文的译文仍暴露链接部分覆盖/错位、图4/图5 内文字丢失与对齐错误、`[0, 1], ,` 多逗号、表2 旋转列标题未翻译、表3 部分翻译、进度卡 0%/计时不更新等问题。用户要求 0.6.0 一次交付，并主要参考 PDFMathTranslate-next、zotero-pdf2zh 的实现思路。

## 决策

1. **链接**：以链接矩形下的完整文本为锚，复合编号（3.1/3.4）与上标（10）不截断；同段引用簇（[4, 7, 18]）按源顺序配对；先定位译文段落再匹配；歧义用相对位置/公式框兜底并记录 warning。
2. **图内文字**：翻译并保持原布局——图4 横坐标恢复；图5 行标签中文竖排、字形正立、保持右对齐；图注翻译；修复 `[0, 1], ,`。BabelDOC typesetting 不能保持时，允许用 PyMuPDF 在输出 PDF 上按原 bbox/旋转/对齐后处理（仅图区域）。
3. **表格**：先对齐 pdf2zh_next 的 BabelDOC 配置并验证表2/4/5；旋转表头翻译后中文竖排、字形正立、保持原列位置；表格内容按文本类型判定（专名/缩写/数字/代码保留，普通英文词与整句翻译），事后做中文有效性校验并回退。
4. **进度**：基于本地 BabelDOC 进度事件与每秒计时；显示“模型正在翻译（已用时 mm:ss）”；阶段权重推进；不为进度发送额外模型请求。
5. **参考实现**：阅读 PDFMathTranslate-next（主）与 zotero-pdf2zh（补充），只借鉴思路与配置，不复制代码；结论写入 docs/research/pdf2zh-reference.md。
6. **交付**：0.6.0 一次交付全部；真实重跑该论文双语一次作为最终验收，单语用 mock/replay。

## 后果

- 链接覆盖范围从“单字符/部分编号”变为完整编号、上标与引用簇；仍需对极少数无法定位的链接记录 warning。
- 图内文字与旋转表头保持原布局，需要 BabelDOC 参数对齐或 PDF 后处理；实现复杂度高于纯规则修补，但避免继续堆叠启发式补丁。
- 表格内容按语义而非几何角色翻译，表3 不再出现“部分翻译部分未翻译”；短专名/缩写保持原文。
- 进度在长请求期间不再停在 0% 或 0:00；显示的是本地计时与阶段进度，不是模型实时百分比。
- 0.6.0 为行为变更，需要完整发布流程与发布说明。
