# 翻译失败也导入已生成的 PDF（降级输出）

## 背景

2026-10-21 的 `2026-10-21T09-37-18-320Z-JYCINM3Z` 日志显示：602 段中 595 段成功，第 8 页 Table 1 的 7 个表头专名（`harrison`、`russellmitchell`、`santos` 等）被 0.5.1 的表头严格规则判为“未翻译的英文原文”；补译后仍保留原文，旧策略把任何失败段都升级为整篇失败，丢弃已经排版完成的 PDF，双语与单语都无法导入。

## 决策

只要 BabelDOC 已产出 PDF 且至少一段真正翻译成功，任何段落级失败、结构性质检失败、鉴权/额度等服务商错误都降级为完成警告并导入译本；失败段落保留原文。完全没有产物，或翻译失败且 0 段成功时仍整篇失败、不导入；全部内容按保护规则保留的文档正常导入。请求的输出模式缺失时，改为导入已生成的另一种产物并警告。

同时为表头单元格增加单令牌专名的保守回退：单个拉丁词、非黑名单通用表头词、非缩写、非常见功能词且无常见英文构词后缀时，模型原样返回视为保留原文；通用表头（Label、Year、Method 等）仍必须翻译。

## 后果

- 用户更可能拿到带少量英文的译本，而不是一无所获；完成提示标注降级并显示保留段数，`job_finished` 日志给出失败段落的页码、段落、原因及日志路径。
- 严格完整性不再是产品约束；测试从“失败即无产物”改为验证降级警告与硬失败边界（无产物/0 段成功）。
- 完成提示会显示“已完成（降级导出）”与保留原文的段数。
- 自 0.5.2 起生效。
