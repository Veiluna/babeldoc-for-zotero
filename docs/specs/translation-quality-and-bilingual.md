# 翻译质量修复与双语 PDF

## 问题描述

用户提供的 Chen 论文原文、译文和两份日志暴露出：摘要在主翻译和合并补译后均因样式占位符不完整而保留原文；行内 `n²+1` 被拆散、`N_f` 下标错位；引用样式将普通正文染蓝；译文丢失原文 201 个内部跳转及 6 个外部链接。另一份日志来自不同论文，第二次请求发生连接错误，并非请求次数达到上限。

## 解决方案

先交付翻译质量、表头规则及请求策略修复 PR，再交付双语输出和环境设置 PR。基线为已合并 PR #12 的 main，保留现有 Unicode 检索及阶段计时修复。用户于 2026-10-20 确认以下全部决策与七张票据，随后明确授权实现、验证、提交和发布 PR。

## 用户故事

1. 作为论文阅读者，我希望摘要、正文及其他应译内容尽量全部完成；若 BabelDOC 已产出 PDF 且至少一段翻译成功，即使仍有段落失败也导入译本并明确警告，失败段落保留原文，避免一无所获（0.5.2 降级输出决策，取代“全部完成才导入”的旧故事）。
2. 作为论文阅读者，我希望行内公式整体嵌入译句，上下标和原始数学含义保持完整。
3. 作为论文阅读者，我希望引用保持正确颜色和可点击目标，普通正文不受链接样式污染。
4. 作为论文阅读者，我希望表格题注与表外正文被翻译；表格内容（表头/表体/旋转表头）与表注/表外附注（星号说明、来源注释）在当前版本保留原文（0.7.0 起封存，见 ADR 0007 与 docs/archive/table-translation.md）。
5. 作为接口使用者，我希望单次最大输出固定为 50000 token，单篇请求不限次数，失败段落始终合并补译，短暂连接故障自动重试。
6. 作为 Zotero 用户，我希望选择单语或左右双语附件，双语左原文、右译文，引用在同侧跳转。
7. 作为 Zotero 用户，我希望先检测本机翻译环境，看到具体故障，再自行决定修复，并在紧凑的设置界面找到项目主页。

## 实现决策

### 翻译与完整性

- 标题、摘要、正文与图表题注属于应译内容。按既有选项保留的参考文献不计为失败；表格内容（表头/表体/旋转表头）与表注/表外附注 0.7.0 起封存、保留原文，不做内容规则送译（封存前规则见 ADR 0006 与 archive 文档）。
- 始终执行一轮合并补译，不逐段无限重发。补译后若仍有应译内容失败，但 BabelDOC 已产出 PDF 且至少一段翻译成功，则降级导入译本：失败段落保留原文，进程发出 ZTF_WARNING（degraded=true）并在 job_finished 记为 warning，给出页码、段落及原因；只有完全没有产物，或翻译失败且 0 段成功时，进程才报告失败且队列不导入任何译本；全部内容按保护规则保留的文档仍视为成功。
- 表格内容当前版本不翻译、不产生表格相关提示；题注与表外正文照常翻译（0.7.0 起封存，见 ADR 0007）。
- 送译前将完整行内公式保护为原子，包含底数、上下标及相邻运算符；还原时整体恢复原始字形及相对位置。已正确的独立公式及 `O(n²)` 不得退化。
- 能正常保持的局部样式继续保留；妨碍可靠翻译时，可在该段的合并补译中简化为正文样式，公式与引用仍受保护。引用颜色仅作用于引用本身。
- 捕获原文链接和目标，将译文点击区域绑定至重新排版后的引用位置；内部目的地映射至对应目标，外部 URI 保持不变。不把原文矩形直接复制到译文位置。

### 表格（0.7.0 起封存，见 ADR 0007）

> 0.7.0 暂停表格翻译：表内单元格保留原文，仅题注与表外正文翻译。以下条款为封存前设计，恢复时参考 docs/archive/table-translation.md。


- 翻译顶部多层列标题及左侧行标题；表头普通英文词必须翻译。Method、Precision、Recall 等栏目可翻；A-Acc-Chr1、YES/NO 等标识符/缩写保持原文。
- 表体规则（0.7.0，ADR 0006）：只有纯标识符/缩写/数字/URL/代码保留；其余英文（含 1–2 词、人名、产品名、整句）送译。模型原样返回时按 kept_verbatim 保留原字形与位置。
- 事后中文有效性校验只作用于送译短值（词数 ≤3 或长度 ≤40）：空、无 CJK、纯数字/标点、与原文等价 → 回退原文并记录；整句不应用该回退。
- 表格标题及表外说明、缩写解释、星号附注照常翻译；表头排版不得越过单元格或覆盖数据。
- 结合已有版面边界和同批请求中的上下文判断角色，只应用已识别表头的译文。表头无法可靠识别时报告表名与页码；表体仍按内容规则送译（0.7.0 调整，见 ADR 0006），不以“全部保留”代替普通清晰表格的表头翻译。
- 表头排版不得越过单元格、覆盖数据或改变表体；仍无法安全排版的已识别表头属于质检失败，按降级输出规则导入并警告。

### 请求策略

- 运行时强制最大输出 50000，取消单篇请求次数上限，始终启用合并补译。删除三项对应设置控件，历史偏好不再影响这些规则。
- 服务商不支持 50000 时明确失败，不自动降低数值。保留现有明确拒绝参数名时的 max_tokens / max_completion_tokens 切换，数值仍为 50000。
- 连接、超时及服务端暂时故障最多再试两次，间隔 2、4 秒；完成的批次不重发。鉴权、余额不足及明确配置错误直接停止。取消可打断等待。
- SDK max_retries 保持 0。所有网络尝试进入真实请求计数；未取得的实际 token 用量保持未知，不写成零。

### 输出与环境

- 右键 PDF 菜单中的插件子菜单提供“翻译成中文 PDF”（mono）与“生成双语对照 PDF”（dual）两个选项，无 both；同一次翻译不增加模型请求。左右双语每页左原文、右译文，内部跳转保持当前侧。
- ZTF_RESULT 支持 mono、dual 路径；Runner 向队列交付 artifacts 列表，每项具有 kind、path；Importer 分类型命名并标记，译本不可再次入队。
- 环境检测检查 Python、依赖版本、字体、模型资源并运行本机小型处理检查；逐项给出结果、原因和日志。检测不调用翻译 API、不自动下载或修复。已安装不等于检测通过。检测可取消，重复点击不得启动多个探测。
- 保留独立 API 测试连接。缩短源选择框和按钮，窄窗口换行。“安装 / 修复环境”统一改为“修复环境”，包括错误引导。关于部分链接 https://github.com/Veiluna/babeldoc-for-zotero。

## 测试决策

用户确认三个测试边界：翻译进程的 PDF / 协议 / 日志 / 退出结果；临时 Zotero 配置的设置 / 队列 / 附件；环境检测的逐项结果和故障原因。通过这些可观察行为验证，不以私有辅助函数形状替代端到端结果。

- 用模拟接口驱动真实 BabelDOC 0.6.4，覆盖 Chen 第 5 页 n²+1、第 7 页 N_f 及染蓝段落、全部原始链接目标；表格内容 0.7.0 起封存（保留原文、仅题注翻译，见 ADR 0007）。正式测试夹具使用合成资料；用户 PDF 留作本机验收，不公开提交全文。
- 覆盖超过 20 次请求、2 次重试的边界、不可重试错误、取消、严格 50000、旧偏好失效、合并补译仍失败时降级导入并警告、无产物或 0 段成功时仍失败。
- 覆盖 mono / dual 的产物合同、附件标记、左右布局和同侧跳转。开启双语不增加翻译调用。
- 覆盖健康环境、缺失依赖、缺失字体或模型、取消、重复检测；探测不能触发安装或下载。
- 每个 PR 独立完成所有现有 Node/Python 测试、语法检查、回放回归、打包和临时 Zotero 实测，并提供失败前后证据。明确区分模拟接口与真实服务商验证，不消耗用户真实接口额度。
