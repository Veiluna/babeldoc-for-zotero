# 输出保真与进度规格（0.6.0）

## 背景

2026-10-21 的公开论文（Introducing a New Alert Data Set for Multi-Step Attack Analysis）译文暴露 6 类问题，均已在本机原文与 21:19 生成的双语 PDF 上复核：

1. **链接**：148 个源链接只恢复 135 个；`[4, 7, 18]` 只有 7/18 有链接；`3.1` 只覆盖 `3`；`3.2` 丢失；`3.4` 部分覆盖或指向错误；`策略10` 上标、`公式1` 无链接；`第 4 节` 指向错误。
2. **图4/图5 内文字**：第 10-11 页；双语 PDF 左侧原文完整，右侧译文侧图4 横坐标文字整体未绘制；图5 行标签被翻译成中文但失去右对齐。
3. **多逗号**：图5 附近 `[0, 1]` 变成 `[0, 1], ,`。
4. **表2 横坐标**：旋转 90° 的列标题（Network Scans 等）未翻译。
5. **表3 内容**：被识别为 45 个表头 + 126 个表体，表体按几何角色保护，出现部分翻译部分未翻译。
6. **进度**：主翻译单请求约 6.9 分钟无细粒度事件，进度窗口停在 0%；“本阶段已用时 0:00”因异步本地化与每秒刷新竞争而不更新；不能为进度额外发模型请求。

本规格在 0.5.2（降级输出）基础上，定义 0.6.0 的输出保真与进度行为。

## 目标

- 链接：用户列出的 7 类问题逐项通过；链接覆盖完整编号/上标/引用簇，目标正确。
- 图内文字：图4 横坐标恢复；图5 行标签翻译为中文、**竖排但字形正立**、保持原文右对齐；图注正常翻译；`[0, 1], ,` 不再出现。
- 表格：表2/4/5 纳入处理；表2 旋转列标题翻译后**中文竖排、字形正立**、保持原列位置与阅读方向；表3 整句翻译、专名在整句中保留；表1 人名/缩写按 0.7.0 表体规则处理（只有纯标识符/缩写/数字/URL/代码保留，其他人名/产品名送译，模型原样返回按 kept_verbatim 保留；见 ADR 0006）。
- 进度：窗口显示“模型正在翻译（已用时 mm:ss）”并每秒更新；阶段权重推进；请求数不因进度增加。
- 版本：0.6.0；全流程发布（PR / Release / 滚动 updates.json / 市场等待抓取）。

## 非目标

- 不更换 BabelDOC 引擎，不复制 PDFMathTranslate/PDFMathTranslate-next 代码。
- 不新增常驻服务；不新增用户设置项来切换本规格的行为。
- 不追求所有论文的 100% 链接恢复；无法精确定位时按兜底并记录 warning。
- 不翻译图片像素中的文字（无 OCR 的新需求）。

## 参考实现结论

- `PDFMathTranslate-next` 是 BabelDOC 的官方调用方，不直接处理链接/表格：源码中没有 `get_links`/`insert_link`，也没有表格模块。它在 `pdf2zh_next/high_level.py` 中构造 `BabelDOCConfig`（`translate_table_text=True`、`figure_table_protection_threshold=0.9`、`enable_graphic_element_process=True`），并使用 BabelDOC 的 `create_progress_handler` + 管道把进度事件转给 GUI。
- BabelDOC 0.6.4 的 `TranslationConfig.table_model` 已弃用并忽略（`translation_config.py:326`）；表格/图形文字由新的 layout/graphic-element 流程处理。因此 T2/T3 先对齐 pdf2zh_next 的 BabelDOC 参数并用 mock 渲染对比，找出图4/5/表2/表3 的实际开关，再决定最小补丁或 PDF 后处理。
- 只借鉴思路与配置，不复制 AGPL 代码；引用来源写入 `docs/research/pdf2zh-reference.md`。

## 详细设计

### T1 链接恢复（ztf_links.py）

- 锚文本：链接矩形下完整文本优先；复合编号 `3.1`、`3.4` 不被截断；矩形只覆盖 `.1` 或 `3` 时，从同一行上下文恢复完整编号；上标 `10` 保留完整文本。
- 引用簇：同一段落、同一括号列表（如 `[4, 7, 18]`）的数字链接归簇，按源阅读顺序配对译文中的数字；整簇可点击，不丢中间项。
- 定位：先用 BabelDOC 段落映射定位译文段落，再在段落内匹配完整锚；歧义用源/输出相对位置与顺序；失败时用公式框/相对几何兜底并记录 warning。
- 目标：`goto` 目标继续用目标段落/页面映射；为 `第 4 节`、`附录 B`、图表/公式引用补充目标定位测试。
- 验收：7 类问题逐项通过；恢复率 ≥95%；每个链接记录 mapped_by（text / citation_cluster / formula_box / geometry / unresolved）。

### T2 图内文字（图4/图5、多逗号）

- 识别图/图表区域（图片、绘图、热图包围盒内的文字），记录原 bbox、旋转方向与对齐方式。
- 图内文字翻译后按原布局绘制：图4 横坐标恢复；图5 行标签中文**竖排、字形正立**、按原右边界对齐；图注正常翻译。
- 修复 `[0, 1], ,`：定位为段落文本/占位符还原的重复逗号，按标点/占位符校验修复，不新增启发式规则。
- 若 BabelDOC typesetting 无法保持原布局，允许用 PyMuPDF 在输出 PDF 上按原 bbox/旋转/对齐重绘（仅限图区域，Q9）。
- 验收：图4 译文侧存在轴标签；图5 行标签 x1 一致（右对齐）、字形正立且竖排；全文档无 `[0, 1], ,`。

### T3 表格识别与旋转表头

- 先验证 BabelDOC 表格相关配置（`--translate-table-text` 等）对表2/4/5 的效果；不足时扩展 `ztf_table_headers` 的识别范围（宽表、热图、旋转列标题）。
- 旋转表头：未翻译时保持原 90° 旋转；翻译后中文竖排、字形正立，保持原列位置/阅读方向；BabelDOC 不支持时用 PyMuPDF 后处理。
- 图区域（T2）与表格区域分离，避免同区域重复处理。
- 验收：表2 旋转列标题为中文竖排；表4/5 按同规则处理；表1/表3 不回归。

### T4 表格内容规则（0.7.0 调整，见 ADR 0006）

- 文本类型预判：
  - 纯标识符/缩写（`A-Acc-Chr1`、`YES/NO`）/数字/URL/代码（含下划线/连字符标识符）→ 保留原文，不送译。
  - 其余英文（普通英文词、1–2 词、人名、产品名、整句，如 `Benign`、`Network Scans`、`Infiltration Dropbox Download and Cool disk`）→ 送译。
  - 模型原样返回（人名/产品名常见）时走 kept_verbatim，保留原字形与位置；这不是失败。
- 事后校验（Q11）：仅对送译短值（词数 ≤3 或长度 ≤40）校验；模型返回为空、无 CJK、纯数字/标点、或与原文等价 → 回退原文并记录；整句不应用该回退。
- 表头/表体几何角色只用于排版对齐，不再作为翻译门。
- 验收：表3 整句翻译、专名在整句中保留；表2 表体普通英文翻译；无“部分翻译部分未翻译”的几何性遗漏。

0.7.0 补充注记：

- 含数字/版本 token 的短值（如 `Apache Spark 3.5`）仍按标识符保留原文；这是 `is_identifier` 的既有例外，不视为与 Q10“产品名送译”矛盾。
- 模型对这类单元格原样返回（kept_verbatim）属预期，不触发失败；keep 单元格不送译，普通短值若回声会先记 invalid_chinese_fallback 再 kept_verbatim（不计失败）。
- CamelCase/含数字的标识符（如 `ChangeMamba`、`CenterPoint`、`A-Acc-Chr1`）按 `is_identifier` 规则保留原文；普通词形式的产品名/人名（如 `Swin`、`Apache Spark`）仍送译，模型回声时按 kept_verbatim 保留原排版，不视为与“产品名送译”矛盾。

### T5 进度显示

- runner：在阶段切换（准备/模型翻译/排版/收尾）与请求开始/结束时发 `ZTF_PROGRESS`；请求开始状态文案“模型正在翻译”；不新增任何 API 请求。
- queue.js：每秒本地刷新计时；修复异步本地化竞争（同步设置文本、缓存本地化模板、序列号只保护最终格式化）；显示“模型正在翻译（已用时 mm:ss）”；按阶段权重推进进度条，无法动画时以文本+计时为主（Q14）。
- 验收：单请求 6.9 分钟期间计时每秒递增；请求数与翻译批次一致；无额外请求。

## 风险与假设

- 图内文字翻译+保持原布局可能受 BabelDOC typesetting 限制；优先参数对齐，再最小后处理；无法稳定实现时带着证据回退与用户确认，不静默改规则。
- 旋转表头竖排排版若 BabelDOC 不支持，用 PyMuPDF 后处理；需避免与图区域后处理重叠。
- 真实重跑消耗约 2.4 万输出 token；失败则降级 mock/replay 并报告。
- 0.6.0 为行为变更（链接覆盖、图内文字、表格内容规则、进度），发布说明需标注。
